## 5特徴量ルールベースの実装 (Cell 8分析結果に基づく)

### 概要 (Overview)

Cell 8のカテゴリ別特徴量分析から、Human-selectedの特徴的プロファイルを発見:
- **disc_edge_coverage_ratio: 最高 (0.955)** — ディスク辺縁が完全に可視
- **disc_center_dist_ratio: 最低 (0.583)** — ディスクが中心に近い
- **mbss_score: 低め (0.234)** — 人間はMBSSを重視していない

この知見に基づき、既存3特徴量（retina_ratio, mbss_Grad_p90, mbss_score）に
disc_edge_coverage_ratio と disc_center_dist_ratio を追加した5特徴量版を実装。

### 変更元ファイル (Source file)

`ROP_project/bestimage_validation/quality_direction_analysis.ipynb` (Cell 10-12を追加)

### 設計ポイント

| 項目 | 内容 |
|------|------|
| 追加特徴量 | disc_edge_coverage_ratio, disc_center_dist_ratio |
| disc_center_dist_ratio処理 | 反転（低い=良い → negate後MinMax正規化） |
| 高速化 | 全特徴量・Quality Direction・評価結果をプリコンピュート |
| 5-feat Grid | step=0.1, max=0.5 (5次元) |
| 6-feat Grid | step=0.2, max=0.6 (5特徴量+quality_proj) |
| Nested LOVO | プリコンピュートしたキャッシュで高速実行 |

### 変更理由 (Reason for change)

Cell 8のboxplot分析で、Human-selectedが他カテゴリと最も異なるのは
disc_edge_coverage_ratio（最高）とdisc_center_dist_ratio（最低）だった。
現行3特徴量ルールにはこれらが含まれないため、追加して性能改善を検証する。

### Oracle Best Weights

**5-feat Rule oracle:**
- retina_ratio=0.273, Grad_p90=0.182, mbss_score=0.182, edge_cov=0.364, center_dist=0.000

- retina_ratio=0, Grad_p90=0.375, mbss_score=0, edge_cov=0.250, center_dist=0, qproj=0.375

### 解釈 (Interpretation)

1. disc_edge_coverage_ratioは有効（oracle重み0.25-0.36）、disc_center_dist_ratioは無効（重み≈0）
2. mbss_scoreは全フォルドで重み≈0に収束 — 人間はMBSSを重視しない
3. Nested LOVO最高記録48.2%を達成したが、固定重み47.3%からの改善は+0.9ppと控えめ
4. Oracle-Nested gap（8.2pp）が依然大きく、重み選定の不安定さがボトルネック
5. 重み安定性は改善: Grad_p90≈0.33, edge_cov≈0.27, qproj≈0.32で安定

## 失敗症例分析 + 3手法比較 (Cell 13-17)

### 解析目的 (Purpose)

5+QualProj Nested LOVOで過去最高48.2%を達成したが、Oracle 56.4%とのgap (8.2pp) が大きい。
根本原因は重み選定の不安定さ（22症例では最適重みを安定選択できない）。
失敗症例 (P@5=0) の深堀りと、重み選定を回避する3つのアプローチを比較検証する。

### 解析手法 (Methods)

- 対象データ: 22症例, 1327候補画像, 138 human-selected
- 失敗症例: 1632, 1703, 1732, 2289, 2290 (全てP@5=0)

**Cell 13: 失敗症例の深堀り分析**
- 13a: Human画像のランク分布（Rule vs QProj）
- 13b: 特徴量プロファイル比較（AI Top-5 vs Human）
- 13c: フレーム番号分布（時間的不一致の可視化）
- 13d: edge_coverage cutoffの効果（閾値別の候補数・Human生存率）

**Cell 14: Approach A — Rank Fusion（パラメータなし）**
- Borda Count: 各特徴量で独立にランキング → 順位合計
- RRF (Reciprocal Rank Fusion): score = Σ 1/(k + rank_i), k=60
- 構成: Borda-3rule, Borda-3key, Borda-5feat, Borda-5+qproj, RRF-3key, RRF-5feat, RRF-5+qproj

**Cell 15: Approach B — 固定重み（分析由来、学習なし）**
- Equal-3key: Grad=1/3, edge_cov=1/3, qproj=1/3
- Grad重視: Grad=0.4, edge_cov=0.3, qproj=0.3
- QProj重視: Grad=0.3, edge_cov=0.3, qproj=0.4
- Edge重視: Grad=0.3, edge_cov=0.4, qproj=0.3
- 共通: retina_ratio=0, mbss_score=0, disc_center_dist=0

**Cell 16: Approach C — 多段カスケード**
- Stage 1: ハードフィルタ（edge_cov >= threshold, 閾値: 0.75/0.80/0.85/0.90）
- Stage 2: ランキング（rule3, grad_only, grad_qproj, grad_edge_qproj, borda）
- 候補不足時は閾値を段階的に緩和（-0.05ずつ、最小0.0）

**Cell 17: 全手法統一比較**
- 全手法のP@5, VM, パラメータ数を統一テーブルで比較
- Per-case棒グラフ、失敗症例の改善状況
- 横棒グラフで全手法を俯瞰

### 解釈・考察 (Interpretation)

1. **パラメータフリーがOracleに迫る**: Equal-3key (55.5%) が Oracle (56.4%) との差わずか0.9pp。重み学習は不要だった。
2. **3つの有効特徴量**: Grad_p90, edge_cov, qproj の3つを等重みで十分。retina_ratio, mbss_score, disc_center_dist は不要。
3. **Rank Fusion (Borda/RRF) は中程度**: 51.8-53.6% で3-feat Ruleよりは良いがFixed weightsに及ばない。順位合計では重要度の差が表現できないため。
4. **カスケードの強み**: Case 1703で0/5→5/5。edge_cov≥0.85のハードフィルタが低品質候補を排除し、grad_qproj rankingが精度を発揮。
5. **構造的限界**: 1632 (時間的不一致) と 1732 (Human 0件) は全手法で改善不可。
6. **推奨手法**: Equal-3key (Grad=1/3, edge_cov=1/3, qproj=1/3) — パラメータ0、解釈性高、VM=86.4%。カスケードも同精度だが閾値パラメータが1つ必要。

### 重要知見: 不要な特徴量を加えると精度が悪化する

#### 有効な3特徴量

| 特徴量 | 役割 | Oracle重み | 根拠 |
|--------|------|-----------|------|
| **mbss_Grad_p90** | 画像鮮明度 (gradient sharpness) | 0.375 | 全フォルドで安定して高重み |
| **disc_edge_coverage_ratio** | ディスク辺縁の可視性 | 0.250 | Human平均0.955 vs 全体平均0.89、最も人間選択と相関 |
| **quality_proj** | RETFound品質方向投射 | 0.375 | CNN由来の総合品質指標（学習不要） |

#### 不要と判明した3特徴量

| 特徴量 | 不要な理由 |
|--------|-----------|
| **retina_ratio** | Oracle重み=0。フィルタ条件 (`retina_ratio > 0`) としては使うが、ランキングスコアには不要 |
| **mbss_score** | 人間はMBSSを重視しない (Human平均0.234 vs Rule-selected平均0.513)。全フォルドで重み0に収束 |
| **disc_center_dist_ratio** | 分析では Human vs 全体で差が見えるが、全フォルドで重み≈0。ランキングに寄与せず |

#### 特徴量を増やすとむしろ悪化するエビデンス

Rank Fusion (Borda) の結果が最も明確に示している:

| 手法 | 使用特徴量 | P@5 |
|------|-----------|-----|
| Borda-3key | Grad + edge_cov + qproj (3つ) | 51.8% |
| Borda-5feat | 5特徴量全部 (5つ) | 51.8% |
| Borda-5+qproj | 5特徴量 + qproj (6つ) | 51.8% |
| **Equal-3key** | **Grad + edge_cov + qproj (等重み)** | **55.5%** |

- 不要な特徴量を加えても改善せず、Equal-3key (55.5%) より3.7pp低い
- Bordaでは各特徴量が等しい投票権を持つため、ノイズ特徴量 (retina_ratio等) が有効特徴量のシグナルを**希釈**する
- 重み付きスコアリングでは「不要特徴量の重み=0」と学習できるが、22症例ではその選定自体が不安定

#### 教訓

> **22症例の小規模データでは「少数の良い特徴量を等重みで使う」が最適解。**
> 特徴量を増やすほど (1) 重み最適化が不安定化し (2) ノイズ特徴量がシグナルを希釈する。
> retina_ratioは候補のプリフィルタとしては有効だが、ランキングスコアには含めるべきでない。

### qprojなし（RETFound不要）の最適解

qprojを使わない場合の最適解も探索した。RETFoundモデルが不要になるため、推論パイプラインが大幅に簡素化される。

#### 結果

| 手法 | P@5 | VM | RETFound |
|------|-----|-----|---------|
| **C-rule3_thr0.80** (edge_cov≥0.80 + 3feat rule) | **53.6%** | 81.8% | **不要** |
| Borda-3rule | 52.7% | 86.4% | 不要 |
| C-rule3_thr0.85 | 52.7% | 81.8% | 不要 |
| C-grad_edge_thr0.80 | 51.8% | 86.4% | 不要 |
| Equal-2key (Grad+Edge 等重み) | 50.9% | 86.4% | 不要 |
| 3-feat Rule ベースライン | 47.3% | 81.8% | 不要 |
| **Equal-3key (qprojあり)** | **55.5%** | **86.4%** | **必要** |

#### 知見

1. **qprojなし最良: Cascade rule3 thr=0.80 → 53.6%** (ベースライン比+6.3pp)
2. **qproj追加の効果はわずか+1.8pp** (53.6% → 55.5%)
3. qprojなしではretina_ratio/mbss_scoreを含む3-feat ruleが最強 — edge_covフィルタで低品質候補を排除した後はこれらの特徴量もランキングに寄与する
4. edge_covをフィルタとして使い、ランキングはGrad+Edge等重みだと51.8%止まり — フィルタ後のランキングには多様な特徴量が有効
5. Case 1703はqprojなしでも5/5回復（edge_covフィルタの効果が支配的）

#### qprojあり/なしの使い分け

| シナリオ | 推奨手法 | P@5 | 追加コスト |
|----------|---------|-----|-----------|
| RETFoundが使える環境 | Equal-3key (Grad=1/3, edge_cov=1/3, qproj=1/3) | 55.5% | RETFound推論 |
| RETFoundが使えない環境 | Cascade (edge_cov≥0.80 + rule3) | 53.6% | なし |
| 差分 | — | +1.8pp | — |

> **RETFoundの寄与は+1.8ppに限定される。** edge_covハードフィルタが精度向上の主因（+6.3pp）であり、推論コストとのトレードオフ次第でqprojは省略可能。

## 正規化手法の比較: MinMax vs Z-score

### 解析目的 (Purpose)

現行のMinMax正規化 `(x - min) / (max - min)` は外れ値に敏感であり、特にフィルタ前後で正規化範囲が変わる問題がある。Z-score正規化 `(x - mean) / std` はmean/stdがより安定なため、改善が期待された。

### 解析手法 (Methods)

以下の3条件で MinMax と Z-score を比較:
1. **フィルタなし + 固定重み**: 全候補を正規化してスコアリング
2. **カスケード + フィルタ後再正規化**: edge_covフィルタ後の候補で正規化
3. 特徴量: 3-feat Rule, Equal-2key, Equal-3key, 各種Cascade

### 主要な結果 (Results)

#### フィルタなし（固定重み）

| 手法 | MinMax | Z-score | 勝者 |
|------|--------|---------|------|
| 3-feat Rule (0.4/0.4/0.2) | 47.3% | **49.1%** | Z-score (+1.8pp) |
| Equal-2key (Grad+Edge) | 50.9% | **51.8%** | Z-score (+0.9pp) |
| **Equal-3key (Grad+Edge+QProj)** | **55.5%** | 53.6% | **MinMax (-1.8pp)** |

#### カスケード（フィルタ後再正規化）

| 手法 | MinMax | Z-score | 勝者 |
|------|--------|---------|------|
| **C-rule3_thr0.80** | **54.5%** | 52.7% | **MinMax (-1.8pp)** |
| C-rule3_thr0.85 | **53.6%** | 52.7% | MinMax (-0.9pp) |
| C-grad_only_thr0.80 | 50.0% | 50.0% | 同率 |
| C-equal3_thr0.80 | 48.2% | **49.1%** | Z-score (+0.9pp) |

#### 全手法サマリ（P@5降順）

| 手法 | MinMax | Z-score | 最良正規化 |
|------|--------|---------|-----------|
| Fixed: Equal-3key | **55.5%** | 53.6% | MinMax |
| C-rule3_thr0.80 | **54.5%** | 52.7% | MinMax |
| C-rule3_thr0.85 | **53.6%** | 52.7% | MinMax |
| Fixed: Equal-2key | 50.9% | **51.8%** | Z-score |
| Fixed: 3-feat Rule | 47.3% | **49.1%** | Z-score |

### 解釈・考察 (Interpretation)

1. **Z-scoreはシンプルな構成でのみ有効**: 2-3特徴量の単純なスコアリングでは+0.9〜1.8ppの改善
2. **上位手法ではMinMaxが優位**: Equal-3key (55.5%) やCascade rule3 (54.5%) ではMinMaxが-1.8ppの差をつけて勝利
3. **理由の考察**: MinMaxは[0,1]に正規化されるため、重みの効果が直感的かつ安定。Z-scoreは値域が無制限で、特徴量間のスケールバランスが特徴量の分布形状に依存してしまう。特にqprojのように分布が正規分布に近くない特徴量では、Z-scoreの仮定が合わない可能性がある
4. **フィルタ後再正規化との相性**: MinMaxはフィルタ後に再正規化すると候補間の差が拡大する効果があり、これがランキング精度に寄与。Z-scoreではこの「拡大効果」が小さい

### 結論

> **MinMax正規化が現行の最適解。** Z-scoreへの変更は不要。
> Z-scoreはシンプルな構成（2-3特徴量、フィルタなし）では若干の改善を示すが、最良手法（Equal-3key, Cascade）ではMinMaxに劣る。
