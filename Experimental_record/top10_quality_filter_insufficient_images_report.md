## 1. 質問と回答

### Q1: 画像不足（33 videos）の場合、少ない画像のままで解析に回されているか？

**はい、その通りです。**

画像不足の動画は、選出できた画像（1〜4枚）がそのまま解析に使用されています。
画像を水増し（複製）したり、除外したりする処理は行われていません。

### Q2: 該当画像が0枚の動画はあったか？

**0枚の動画はありませんでした。**

出力ログより：
- `特徴量なし: 0`（全347動画で少なくとも1枚以上の有効画像が存在）
- `最小選出数: 1枚`（最も少ない動画でも1枚は選出されている）

## 2. 選出アルゴリズムの詳細

### フィルタリングフロー

```
動画ごとの全Good+Fair画像
    ↓
[有効画像フィルタ] retina_ratio > 0 かつ 非NaN
    ↓
  有効画像 = 0枚 → スキップ（「特徴量なし」にカウント）★今回は該当なし
  有効画像 ≥ 1枚 → 次のステージへ
    ↓
[Stage 1] disc_edge_coverage_ratio >= 0.80 の画像を
          0.4×retina + 0.4×grad + 0.2×mbss のスコアで降順ソート → 上位K枚
    ↓
  K枚に満たない場合
    ↓
[Stage 2 (Fallback)] Stage1で選ばれなかった残りの有効画像を
                      retina_ratio 降順で補完
    ↓
  それでもK枚に満たない場合 → 「画像不足」にカウント（ある分だけで解析）
```

## 4. まとめ

1. **画像不足の動画は除外されず、選出できた画像のままで解析されている**
   - Top-5の場合：33動画が5枚未満（1〜4枚）で解析
   - Top-10の場合：74動画が10枚未満で解析

2. **0枚の動画は存在しない**（特徴量なし = 0）
   - ただしコード上、もし0枚になった場合はその動画はスキップされ解析対象外となる

3. **最小選出数は1枚**
   - 一部の動画では1枚の画像のみで分類判定が行われている

4. **臨床的な留意点**
   - 画像枚数が少ない動画では、majority voteなどの集約手法の信頼性が低下する可能性がある
   - 特に1枚のみの動画では、その1枚の画像の予測がそのまま最終判定となる
