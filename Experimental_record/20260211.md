## 患者単位 Majority Vote による ROP分類性能評価

### 概要 (Overview)

Top-K品質フィルタリングで選出した画像群の予測を、患者（video_id）単位で多数決集約（Majority Vote）し、画像単位評価と比較する解析ノートブックを作成した。

### 新規作成ファイル (New file)

`ROP_project/multicenter_study/evaluate_majority_vote.ipynb`

### セル構成 (11 cells)

| Cell | Type | 内容 |
|------|------|------|
| 0 | Markdown | タイトル・概要・集約方法説明 |
| 1 | Code | Imports & Config |
| 2 | Code | データ読み込み・結合・ラベル一貫性チェック |
| 3 | Code | Top-10/Top-5 選出 (C-rule3_thr0.80) |
| 4 | Code | Majority Vote 集約関数 (Hard/Soft) |
| 5 | Code | 評価関数定義 |
| 6 | Code | 集約 & 評価実行 (6条件: All/Top-10/Top-5 x Hard/Soft) |
| 7 | Code | 比較テーブル (Multiclass + Binary) |
| 8 | Code | Summary: Soft Vote vs Per-Image Baseline |
| 9 | Code | RW-ROP / Treatment 閾値最適化 |
| 10 | Code | 結果保存 (JSON, CSV) |

### 集約方法

- **Hard Vote**: 各画像の予測クラス（離散値）の最頻値（mode）を患者単位の予測とする。例: 5枚中3枚が Zone II → 患者予測は Zone II。
- **Soft Vote**: 各画像のクラス別予測確率（softmax出力）を画像間で平均し、その平均確率から患者単位の予測を決定する。
  - **Multiclass (Zone/Stage/Plus)**: 各クラスの確率を平均 → argmax（最大確率のクラスを予測）
    - 例: Zone の場合、5枚の `[P(I), P(II), P(III)]` を要素ごとに平均 → `[0.15, 0.60, 0.25]` → 予測: Zone II
  - **Binary (Treatment/AROP)**: 陽性確率 `P(positive)` を平均 → 閾値 0.5 で判定
    - 例: Treatment の場合、5枚の `P(treat=1)` = [0.8, 0.9, 0.7, 0.6, 0.85] → 平均 0.77 >= 0.5 → 予測: Treatment陽性
  - **RW-ROP (derived)**: Zone/Stage/Plus の集約済み確率から導出
    - `P(RW-ROP) = 1 - (1 - P(Plus=2)) x (1 - P(Stage=3)) x (1 - P(Zone=I))`
    - P(RW-ROP) >= 0.5 で陽性判定
- **Soft Vote の利点**: Hard Vote は「予測クラス」しか使わないが、Soft Vote は確率の大きさ（モデルの確信度）も反映するため、境界付近の症例でより安定した予測が得られる。

## 予測一致率分析: 信頼度指標としての活用

### 解析目的 (Purpose)

同一 video_id 内の画像間で予測がどの程度一致しているかを分析し、一致率が信頼度指標として使えるか検証する。

### 解析手法 (Methods)

- 対象: 全6,448画像 (347 video_ids)
- 一致率 = (最頻予測と同じ予測をした画像数) / (全画像数)
- 各タスクについて一致率を算出し、一致率別の多数決正解率を比較

### 主要な結果 (Results)

#### Per-Video Agreement Rate
| Task | Mean | 100%一致 | <90% | <60% |
|------|------|----------|------|------|
| Zone | 0.892 | 187/347 | 81 | 26 |
| Stage | 0.908 | 200/347 | 64 | 24 |
| Plus | 0.927 | 237/347 | 55 | 18 |
| Treatment | 0.969 | 297/347 | 23 | 8 |
| RW-ROP | 0.933 | 234/347 | 43 | 19 |

#### Agreement vs Correctness
| Task | 正解率 (>=90%) | 正解率 (<90%) | 差分 |
|------|----------------|---------------|------|
| Zone | 0.837 (227例) | 0.592 (120例) | **+24.5pp** |
| Stage | 0.814 (247例) | 0.550 (100例) | **+26.4pp** |
| Plus | 0.962 (265例) | 0.585 (82例) | **+37.7pp** |
| Treatment | 0.978 (313例) | 0.765 (34例) | +21.3pp |
| RW-ROP | 0.960 (275例) | 0.694 (72例) | **+26.6pp** |

### 解釈・考察 (Interpretation)

1. **347動画中、約7割はそもそも全画像で予測が100%一致** → Majority Vote の効果が限定的な理由。
2. **予測一致率 < 90% の症例は正解率が大幅に低下** (Plus: 37.7pp, RW-ROP: 26.6pp)。モデルが迷っている症例 = 間違いやすい症例。
3. **臨床応用**: 一致率を信頼度指標として出力し、低一致率 (<90%) の患者にフラグ → 手動レビューを推奨する運用が有効。
4. RW-ROPで一致率 <70% の35動画 (10%) は、正解/不正解がほぼ半々（モデルの判断境界上の症例）。

## エッジ検出・ノイズマップによる患者内類似度削減の検証

### 解析目的 (Purpose)

Pairwise学習の失敗原因である「患者ID記憶」を、画像変換（エッジ検出・ノイズマップ）により緩和できるかを検証する。同一患者内のcosine類似度を下げ、品質差を強調できれば、CNN pairwise学習が改善される可能性がある。

### 解析手法 (Methods)

- 対象データ: 22ケース、6,037枚（has_lens=True）、138枚のhuman-selected best
- 実験1（サンプル分析）: 5ケース×50枚=250枚で各種変換のCNN特徴量類似度を比較
- 実験2（全データ評価）: 全22ケースでLOVO-CVによるTop-5 Precision評価
- CNN: frozen EfficientNet-B0 (ImageNet pretrained), 1280次元特徴量
- RETFound quality_proj: 既存の1024次元特徴量を参照

### 実験1: エッジ変換と類似度分析

#### 変換手法
- **エッジ検出**: Canny, Sobel, Laplacian, Multi-channel (Canny+Sobel+Lap)
- **Quality Maps** (品質マップ): Laplacian分散 + Gradient Magnitude + 高周波エネルギー → 3ch
- **Noise Maps** (ノイズマップ): ハイライト検出 + ヘイズ検出 + 局所ノイズ → 3ch

#### 結果: CNNの特徴量類似度

| 入力 | Patient ID Gap | Quality Gap | **SNR (Quality/ID)** |
|------|---------------|-------------|---------------------|
| Raw RGB | 0.102 | 0.369 | 3.62 |
| Canny | 0.071 | — | — |
| Sobel | 0.089 | 0.280 | 3.16 |
| Edge Multi-ch | 0.090 | 0.306 | 3.39 |
| Quality Map | 0.077 | 0.230 | 2.98 |
| **Noise Map** | **0.054** | **0.251** | **4.63** |
| Quality+Noise concat | 0.062 | 0.243 | 3.92 |

- Noise MapがPatient ID gapを47%削減、SNRを28%改善（最良）
- ただしQuality Gapも32%低下（品質識別力も落ちる）
- エッジ検出は「鈍器」— 血管パターン（患者ID）は残り、品質の微妙な差は消える

#### スカラー特徴量とHuman選択の相関

| Feature | Human Mean | Other Mean | Diff | 解釈 |
|---------|-----------|------------|------|------|

### 実験2: 全データLOVO-CV評価

Noise Mapから「ノイズ方向ベクトル」(noise_proj)を計算し、Equal-3keyに追加して評価。

| Method | Top-5 Precision | Video Match | vs Baseline |
|--------|----------------|-------------|-------------|
| **equal_3key** (baseline) | **54.0%** | 86.4% | — |
| + noise_proj (4key) | 49.0% | 90.9% | **-5.0pp** |
| + highlight (4key) | 43.0% | 77.3% | -11.0pp |
| + both (5key) | 41.0% | 77.3% | -13.0pp |
| 3key - noise penalty | 50.0% | 90.9% | -4.0pp |
| noise_proj 単体 | 21.0% | 54.5% | — |
| highlight 単体 | 3.0% | 9.1% | — |

### 主要な結果 (Results)

1. **ノイズマップはPatient ID信号の削減に成功**（Gap: 0.102→0.054, -47%）
2. しかし**品質信号も同時に低下**（Gap: 0.369→0.251, -32%）
3. ノイズ特徴量をEqual-3keyに追加すると**全て性能低下**（-4pp〜-13pp）
4. エッジ検出（Canny/Sobel）も同様に鈍器的で品質信号を削る
5. ノイズマップ単体 (21%) はランダム (~10%) より良いが、既存特徴量には遠く及ばない

### 解釈・考察 (Interpretation)

- エッジ/ノイズ変換は「鈍器」— 患者IDと品質の**両方**を一律に削減する
- EfficientNet-B0（ImageNet学習済み）はノイズマップから品質情報を効果的に抽出できない
- 既存3特徴量（Grad_p90, edge_cov, qproj）が品質の本質を既に捉えており、追加特徴量はノイズを加えるだけ
- Oracle上限56.4% vs Equal-3key 55.5% = **改善余地0.9pp**で、新特徴量で超えるのは困難
- Pairwise学習でこのアプローチを使っても、根本的なデータ量不足（22ケース）は解決しない
