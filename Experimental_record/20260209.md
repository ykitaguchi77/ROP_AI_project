## Hybrid CNN + Handcrafted Feature Ranking Model の実装

### 概要 (Overview)

画像ベースPairwise Ranker（EfficientNet-B0 fine-tune）がTop-5 Precision 0%で完全に失敗した問題（患者identity学習）を解決するため、Frozen CNNの特徴量抽出 + 手動特徴量を結合した軽量MLPランキングモデルを実装した。

### 変更元ファイル (Source file)

- 参照元: `ROP_project/bestimage_validation/train_pairwise_ranker.ipynb` (15次元手動特徴量MLP)
- 参照元: `ROP_project/bestimage_validation/train_image_pairwise_ranker.ipynb` (画像ベースPairwise Ranker)
- 新規作成: `ROP_project/bestimage_validation/train_hybrid_ranker.ipynb`

### Before / After 比較

| 項目 | Before (Image Ranker) | Before (Feature MLP) | After (Hybrid) |
|------|----------------------|----------------------|-----------------|
| CNN backbone | EfficientNet-B0 fine-tune | なし | EfficientNet-B0 **frozen** |
| 特徴量次元 | 1280 (fine-tuned) | 15 (handcrafted) | 32 (PCA) + 15 (handcrafted) = 47 |
| MLPパラメータ数 | ~330K | ~1,500 | ~1,700 |
| 前処理 | なし | MinMaxScaler | StandardScaler→PCA (CNN) + MinMaxScaler (handcrafted), per-fold |
| CNN特徴量キャッシュ | なし | N/A | `lens_crops/cnn_features_effb0.npz` |
| PCA次元 | N/A | N/A | 探索: {8, 16, 32, 64}、3-fold pilotで選定 |
| リーク防止 | なし | case単位 | per-fold fit/transform |

### アーキテクチャ

```
[Frozen EfficientNet-B0]        [15 Handcrafted Features]
        |                                |
   1280-dim (cached)              MinMaxScaler (per-fold)
        |                                |
   StandardScaler + PCA (per-fold)       |
   1280 → best_dim                       |
        |                                |
        +----------- concat ------------+
                       |
                  (best_dim+15) input
                       |
                 BatchNorm1d
                       |
                 Linear → ReLU → Dropout(0.5)
                       |
                 Linear → ReLU
                       |
                 Linear → score
```

### 設計上のポイント

1. **Backboneは完全凍結**: fine-tuneしない → patient identity学習を防止
2. **CNN特徴量はキャッシュ**: 6,689枚×1280次元を`.npz`で保存（1回の抽出で以降は即座にロード）
3. **PCA per-fold**: 学習データのみでfit、テストデータにtransformでリーク防止
4. **小さいMLP**: ~1,700パラメータで過学習しにくい構造
5. **Ablation**: CNN寄与を定量化するため手動特徴量のみのベースラインも報告

### 変更理由 (Reason for change)

- 画像ベースモデル（EfficientNet-B0 fine-tune）は22症例・6,689画像という小規模データでpatient identityを学習してしまい、Top-5 Precision 0%
- 手動特徴量のルールベース手法は47-54%を達成しているが、CNNが持つ画像レベルの情報を活用できていない
- Frozen CNNで特徴量を抽出しPCAで圧縮することで、patient identity問題を回避しつつCNN特徴量の恩恵を得る

### 主要な結果 (Results)

#### PCA次元探索（3-fold pilot: Case 1227, 1363, 1376）

| PCA次元 | Top-5 Precision | MRR | NDCG@5 | Video Match |
|---------|----------------|-----|--------|-------------|
| 8 | 0.000 | 0.054 | 0.000 | 0.000 |
| 16 | 0.000 | 0.036 | 0.000 | 0.000 |
| 32 | 0.000 | 0.061 | 0.000 | 0.000 |
| **64** | **0.200** | **0.368** | **0.233** | **0.333** |

→ Best PCA dimension: **64**

#### 全手法比較（22-fold LOVO CV）

| 手法 | Top-5 Precision | Video Match | NDCG@5 | MRR |
|------|----------------|-------------|--------|-----|
| **Rule-based (retina+mbss)** | **0.545** | **0.864** | **0.510** | **0.640** |
| Feature MLP (15→64→32→16→1) | 0.191 | 0.500 | 0.212 | 0.374 |
| Handcrafted-only MLP (15→32→16→1) | 0.082 | 0.273 | 0.070 | 0.136 |
| Hybrid CNN+Hand (PCA=64, 79→32→16→1) | 0.082 | 0.318 | 0.101 | 0.234 |

- CNN寄与（Top-5 Precision）: Hybrid - Handcrafted-only = **0.000（0.0%）**
- MRRのみ若干改善: 0.136 → 0.234

### 解釈・考察 (Interpretation)

1. **Hybrid モデルはルールベースに大幅に劣る**: Top-5 Precision 8.2% vs 54.5%
2. **Frozen ImageNet CNN特徴量の寄与はほぼゼロ**: Hybrid ≒ Handcrafted-only（Top-5 Precision同値）
3. **MLPベースの手法は全てルールベースを下回る**: 22症例・~1,200ペアではMLPが重み付けパターンを学習できない
4. **根本原因**:
   - データが少なすぎる（22症例、ペア数~1,200）→ MLPが汎化できない
   - ImageNet事前学習の特徴量は眼底画像の「品質」に対して情報量不足
   - ルールベースの3特徴量の重み付け（retina_ratio 0.4 + mbss_Grad_p90 0.4 + mbss_score 0.2）が既に強力で、学習で改善する余地が小さい
5. **今後の方向性**:
   - 眼底画像で事前学習済みBackbone（RETFound等）を使うことでCNN特徴量の質を向上
   - ルールベースの重み最適化（grid search/Bayesian optimization）がより現実的
   - データ増加（症例数の拡大）が根本的解決策

## RETFound Backbone 統合によるHybrid Rankerの改善

### 概要 (Overview)

Frozen EfficientNet-B0 (ImageNet事前学習) の特徴量ではCNN寄与がゼロだった問題に対し、
RETFound (160万枚カラー眼底写真でMAE事前学習したViT-Large) に置き換え、
眼底ドメインに特化した1024次元特徴量を抽出するバックボーン切り替え機能を実装した。

### 変更元ファイル / 新規作成ファイル

- 変更: `ROP_project/bestimage_validation/train_hybrid_ranker.ipynb` — backbone選択対応
- 新規: `ROP_project/bestimage_validation/retfound_utils.py` — RETFound モデル定義 + 重みローダー

### Before / After 比較

| 項目 | Before | After |
|------|--------|-------|
| Backbone | EfficientNet-B0 (ImageNet) のみ | `retfound` / `efficientnet_b0` 切り替え可能 |
| CNN特徴量次元 | 1280 固定 | 1024 (RETFound) or 1280 (EfficientNet) |
| 入力画像サイズ | 384 固定 | 224 (RETFound) or 384 (EfficientNet) |
| キャッシュファイル | `cnn_features_effb0.npz` 固定 | backbone名に応じて自動切り替え |
| Config.backbone | なし | `'retfound'` / `'efficientnet_b0'` |
| FoldPreprocessor | zero_vec = 1280次元固定 | `cnn_feature_dim` パラメータで動的 |
| 比較テーブル | 2手法 | EfficientNet Hybrid + RETFound Hybrid を並列表示 |

### 新規ファイル: `retfound_utils.py`

RETFound公式リポ (rmaphoh/RETFound_MAE) から必要部分のみ抽出した自己完結モジュール：
- `VisionTransformer`: global average pooling対応のViTクラス
- `RETFound_mae()`: ViT-Large設定 (patch16, embed_dim=1024, depth=24, num_heads=16)
- `interpolate_pos_embed()`: 異なる解像度のpositional embedding補間
- `load_retfound()`: 重みロード + freeze + eval の一括関数

### アーキテクチャ（変更後）

```
[Frozen RETFound ViT-Large]     [15 Handcrafted Features]
        |                                |
   1024-dim (cached)              MinMaxScaler (per-fold)
        |                                |
   StandardScaler + PCA (per-fold)       |
   1024 → best_dim                       |
        |                                |
        +----------- concat ------------+
                       |
                  (best_dim+15) input
                       |
                 BatchNorm1d → Linear → ReLU → Dropout(0.5)
                       |
                 Linear → ReLU → Linear → score
```

### 変更理由 (Reason for change)

- ImageNet事前学習のEfficientNet-B0特徴量は眼底画像の「品質」判別に無関係な情報が多く、CNN寄与がゼロ
- RETFoundは160万枚のカラー眼底写真でMAE事前学習されており、眼底ドメインに特化した表現を獲得
- 眼底品質に関連する特徴量（血管の鮮明さ、視神経乳頭の位置等）がRETFoundの特徴空間に含まれることが期待される

## Cosine類似度ベースの学習不要ランキング

### 概要 (Overview)

MLP学習ベースのアプローチ（Hybrid RETFound+MLP: 10.0%）が22症例で汎化できない根本原因がMLPの学習そのものであると判断し、
ニューラルネットの学習を完全に排除した新手法を実装。RETFound特徴量のcosine類似度を学習不要のスコアリングシグナルとして活用する。

核心アイデアは **Quality Direction Projection**: 各症例で「人間が選んだベスト画像の平均特徴量」と「全画像の平均特徴量」の差分ベクトルを計算し、
訓練症例間で平均・正規化して「品質方向ベクトル」を得る。テスト画像をこの方向に射影して品質スコアとする。

### 新規作成ファイル (Source file)

`ROP_project/bestimage_validation/cosine_similarity_ranking.ipynb`

### Before / After 比較

| 項目 | Before (Hybrid MLP) | After (Cosine Ranking) |
|------|---------------------|----------------------|
| 学習 | MLP pairwise ranking | **学習なし** |
| CNN特徴量の使い方 | PCA圧縮→MLP入力 | cosine類似度 / 方向射影 |
| 重み選定 | なし（固定MLP） | Grid search (nested LOVO-CV) |
| パラメータ数 | ~2,175 (MLP) | 4 (重み係数のみ) |
| リーク防止 | per-fold fit/transform | Quality directionはtrain casesのみ + Nested LOVO |

### 実装した3戦略

1. **Prototype Cosine**: 訓練症例のbest画像との cosine類似度（cos_mean / cos_topk5）
2. **Quality Direction Projection**: 品質方向ベクトルへの射影スコア
3. **統合スコア**: `w1*retina_ratio + w2*mbss_Grad_p90 + w3*mbss_score + w4*quality_proj`
   - Oracle: 全22 foldで最適重みを選定（楽観的上限）
   - Nested LOVO-CV: 外側22-fold × 内側21-fold でバイアスなし評価

### 解釈・考察 (Interpretation)

1. **Quality Direction Projectionは有意義なシグナル**:
   - 単独で41.8%は、CNN特徴量のみ・学習なしとしては良好
   - Video Match 86.4%はルールベース(81.8%)を上回る
   - Oracle統合で+6.4pp改善（47.3%→53.6%）は質方向ベクトルに情報があることを示す

2. **Nested LOVOでは改善せず（-0.9pp）**:
   - Oracle(53.6%) vs Nested(46.4%) = 7.2ppの乖離
   - 21症例の内側CVではバリアンスが大きく、最適重みを安定して選べない
   - 重み空間が広すぎ（2065セット）× 内側症例が少なすぎ（21）の組み合わせ

3. **retina_ratioが不要とされる傾向**:
   - 16/22 foldでretina_ratio=0 → quality_projとmbss_Grad_p90だけで十分と判断
   - しかしFold 1363, 2028, 2232, 2376ではretina_ratio > 0.35 → 症例依存性がある

4. **Prototype cosineは弱い（11.8-19.1%）**:
   - 同一症例内のcosine~0.99という事前予測通り、生cosine類似度では症例内の品質差を捉えられない
   - Quality Direction（差分ベクトル）のアプローチの方が圧倒的に有効

5. **今後の方向性**:
   - **固定重み**（oracle最適: mbss_Grad_p90=0.33, quality_proj=0.56, mbss_score=0.11）で評価する方がNested CVより良い可能性
   - 重み空間を狭める（quality_proj=0.3〜0.5の範囲に制限）ことでNested CVの安定性を改善できる可能性
   - **データ拡大**が根本解決策
