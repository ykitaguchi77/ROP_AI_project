## マルチセンター動画処理ノートブックに動画範囲選択機能を追加

### 概要 (Overview)

`process_multicenter_videos_disc-retina.ipynb` に動画番号の範囲を指定して処理する機能を追加。374番まで処理済みのため、375番以降を追加抽出する用途。

### 変更元ファイル (Source file)

`ROP_project/multicenter_study/process_multicenter_videos_disc-retina.ipynb`

### Before / After 比較

| 項目 | Before | After |
|------|--------|-------|
| 動画選択方法 | RESUME_FROM_LAST（Excelベース再開）のみ | VIDEO_RANGE_START / VIDEO_RANGE_END による番号範囲指定を追加 |
| 番号の意味 | （なし） | ファイル名先頭の番号で指定（例: 375 → 0375_AMU.mov）※ソート順位置ではなく実際のファイル名番号 |
| 設定パラメータ | RESUME_FROM_LAST のみ | VIDEO_RANGE_START=375, VIDEO_RANGE_END=None を追加 |
| メイン処理の動画リスト | 全動画→再開フィルタ | 範囲指定時: ファイル名番号フィルタのみ / 未指定時: 再開フィルタ |
| RESUME_FROM_LASTと範囲指定の関係 | 常にRESUME_FROM_LASTが適用 | 範囲指定時はRESUME_FROM_LASTを自動無効化（中途半端な処理済み動画もスキップせず再処理） |
| 処理開始時の表示 | 範囲情報なし | 対象範囲・最初/最後の動画名(No.xxx)・スキップ無効を表示 |

### 変更理由 (Reason for change)

- 374番までの動画は抽出完了しており、375番以降のみを追加処理する必要があった
- 既存のRESUME_FROM_LAST機能はExcelの処理済みIDに依存するため、明示的な番号指定が必要だった
- 強制終了で中途半端に処理された動画がスキップされる問題を回避するため、範囲指定時はRESUME_FROM_LASTを自動無効化
- 欠番があるためソート順の位置番号とファイル名の番号がずれる問題を修正（位置→ファイル名番号に変更）

## 症例レベルアンサンブル（多数決）によるメトリクス改善の検討

### 概要 (Overview)

`train_rop_classifier_quality_comparison.ipynb` の画像単位予測結果（predictions.csv）を用いて、同一症例（video_id）の全Good画像を多数決アンサンブルした場合の症例レベルメトリクスをシミュレーション分析した。コード変更は行わず、分析結果のみ記録。

### 分析対象ファイル (Source file)

- `ROP_project/multicenter_study/outputs_quality_comparison/good_only/predictions.csv`
- `ROP_project/multicenter_study/outputs_quality_comparison/good_fair/predictions.csv`

### 分析条件

- 症例あたり画像数: good_only 平均14.7枚（中央値14, 最大30）、good_fair 平均19.2枚（中央値21, 最大30）
- アンサンブル方法: 多数決（majority vote）
- バイナリタスク追加検証: 陽性画像比率に対する閾値最適化

### 結果: 症例レベルアンサンブルの効果

#### Multi-class タスク（Zone, Stage）: 改善

| Task | Metric | good_only (Image→Case) | good_fair (Image→Case) |
|------|--------|------------------------|------------------------|
| Zone | Accuracy | 0.711→**0.740** (+2.9%) | 0.714→**0.753** (+3.9%) |
| Zone | Kappa | 0.453→0.458 (+0.5%) | 0.502→**0.537** (+3.5%) |
| Stage | Accuracy | 0.643→**0.654** (+1.1%) | 0.653→**0.667** (+1.4%) |
| Stage | Kappa | 0.650→**0.687** (+3.7%) | 0.667→**0.719** (+5.2%) |

#### Zone クラス別 Sensitivity 変化

| Class | good_only (Image→Case) | good_fair (Image→Case) |
|-------|------------------------|------------------------|
| Zone I | 0.513→0.517 (±0) | 0.458→0.441 (-1.7%) |
| Zone II | 0.884→**0.915** (+3.1%) | 0.860→**0.911** (+5.1%) |
| Zone III | 0.373→0.359 (-1.4%) | 0.473→0.474 (±0) |

- Zone II（多数派）が最も改善。Zone I/IIIのPPVは改善（I: 0.73→0.83 / 0.78→0.88）

#### Stage クラス別 Sensitivity 変化

| Class | good_only (Image→Case) | good_fair (Image→Case) |
|-------|------------------------|------------------------|
| Stage 0 | 0.663→0.656 (-0.8%) | 0.749→0.735 (-1.3%) |
| Stage 1 | 0.684→**0.742** (+5.8%) | 0.555→**0.632** (+7.7%) |
| Stage 2 | 0.365→**0.400** (+3.5%) | 0.447→**0.450** (+0.3%) |
| Stage 3 | 0.841→0.762 (-7.9%) | 0.795→0.750 (-4.5%) |

- Stage 1が最も改善。Stage 3のSensitivityは低下するがPPVは維持

#### Binary タスク（Aggressive ROP, Treatment）: 単純多数決では悪化

| Task | Condition | Image Sens→Case Sens (majority vote) | 原因 |
|------|-----------|--------------------------------------|------|
| Aggressive ROP | good_only | 0.286→**0.111** (-17.5%) | 陽性症例内の正答率中央値5.6% |
| Aggressive ROP | good_fair | 0.447→0.444 (-0.3%) | 陽性症例内の正答率中央値40% |
| Treatment | good_only | 0.696→0.645 (-5.1%) | 陽性症例内の正答率中央値80% |
| Treatment | good_fair | 0.654→0.636 (-1.8%) | 陽性症例内の正答率中央値75% |

#### Binary タスク: 閾値最適化アンサンブルで大幅改善

陽性画像比率（pos_ratio）をスコアとし、閾値を下げることで改善:

| Task | Condition | 最適閾値 | Image Sens→Case Sens | Case F1 | Case AUC |
|------|-----------|----------|----------------------|---------|----------|
| Aggressive ROP | good_only | 0.05 | 0.286→**0.667** | 0.791 | 0.822 |
| Aggressive ROP | good_fair | 0.15 | 0.447→**0.778** | 0.863 | **0.991** |
| Treatment | good_only | 0.20 | 0.696→**0.806** | 0.852 | 0.916 |
| Treatment | good_fair | 0.05 | 0.654→**0.909** | 0.870 | 0.939 |

### 考察

1. **Multi-classタスク**: 多数決アンサンブルで安定して改善。特にKappaの改善が顕著（Stage +3.7〜5.2%）
2. **Binaryタスク**: 単純多数決はクラス不均衡により陽性検出力が低下。閾値を下げたアンサンブルで大幅改善
3. **good_fair > good_only**: 画像数が多いほどアンサンブル効果が大きい
4. **実装推奨**: logit/softmax確率を保存したsoft votingが理想的。現状はargmax予測のみ保存のためhard votingに限定
5. **今後の実装**: 必要時にノートブックへ症例レベル評価セルを追加予定

## クラス不均衡対策ノートブックの作成

### 概要 (Overview)

クラス不均衡に対処するためのWeighted Cross-Entropy / Focal Lossを実装した新規ノートブックを作成。

### 新規作成ファイル (New file)

`ROP_project/multicenter_study/train_rop_classifier_class_balanced.ipynb`

### クラス不均衡の状況 (good_fair)

| Task | Class | Count | Ratio | Weight |
|------|-------|-------|-------|--------|
| Zone | I / II / III | 651 / 3127 / 1200 | 13% / 63% / 24% | 4.8 / 1.0 / 2.6 |
| Stage | 0 / 1 / 2 / 3 | 1969 / 1355 / 823 / 809 | 40% / 27% / 17% / 16% | 1.0 / 1.5 / 2.4 / 2.4 |
| Aggressive ROP | No / Yes | 4750 / 228 | 95% / 5% | 1.0 / 20.8 |
| Treatment | No / Yes | 4351 / 627 | 87% / 13% | 1.0 / 6.9 |

### 実装内容

| 項目 | Baseline (quality_comparison) | Class-Balanced (新規) |
|------|-------------------------------|----------------------|
| Cross-Entropy | weight=None | weight=クラス頻度逆数 |
| Focal Loss | alpha=None, gamma=2.0 | alpha=クラス重み, gamma=2.0 |
| Label Smoothing | 0.15 | 0.1 (少し下げる) |
| Patience | 10 | 15 (少し長めに) |

### 期待される効果

1. **少数クラスの感度向上**: Zone I, Stage 2, Aggressive ROP(Yes)
2. **全体精度の維持または微減**: 多数派クラスの精度がやや下がる可能性あり
3. **Macro F1の改善**: クラス間バランスが取れる

### 次のステップ

1. ノートブック実行 → 結果確認
2. 効果不十分なら WeightedRandomSampler 追加
3. 必要に応じて 2段階学習（バランス→Fine-tune）を検討
