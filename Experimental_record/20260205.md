## Pairwise Ranking Model for Best Image Selection

### 概要 (Overview)
ヒトの専門家が選択したベスト眼底画像と同じ画像をAIが選択できるよう、Pairwise Rankingモデルを実装した。

### 背景 (Background)
- 現状のルールベースAIは54.5%の画像一致率（compare_ai_human_top.ipynbより）
- ルールベースアプローチ: `score = 0.4×retina_ratio + 0.4×mbss_Grad_p90 + 0.2×mbss_score`
- 目標: 学習ベースRankerで65-75%の一致率を達成

### 手法 (Methods)

#### データ準備
- **入力候補**: 各動画からルールベースAIで上位100枚をフィルタリング
- **正例**: ヒトTop5（YF, HKの評価者が選択した画像）
- **負例**: 残り95枚
- **ペアワイズサンプル**: 正例×負例のペアを生成（各正例につき10ペア）

#### モデルアーキテクチャ
```
Feature-based MLP Ranker
Input(15) → BatchNorm → FC(64) → ReLU → Dropout(0.3)
         → FC(32) → ReLU → Dropout(0.3)
         → FC(16) → ReLU
         → FC(1) → Score
```

#### 特徴量（15次元）
- 構造系: retina_ratio, retina_area
- Disc系: disc_detected, disc_edge_coverage_ratio, disc_area_ratio, disc_center_dist_ratio, disc_pos_ok
- 品質系: mbss_L_multi, mbss_HF_ratio, mbss_Spec_centroid, mbss_Grad_p90, mbss_score
- Disc鮮明度: disc_core_score, disc_ring_score
- 色彩: S_mean

#### 損失関数
- **Margin Ranking Loss** (margin=1.0)
- `loss = max(0, margin - (score_positive - score_negative))`

#### 学習設定
| パラメータ | 値 |
|-----------|------|
| Learning rate | 1e-3 |
| Batch size | 64 |
| Epochs | 100 |
| Early stopping | 10 epochs |
| Weight decay | 1e-4 |

#### 評価方法
- **Leave-One-Video-Out (LOVO) 22-fold CV**
- 評価指標: Top-5 Precision, Top-5 Recall, NDCG@5, MRR, Video Match Rate

### 実装詳細

#### dataset.py
- `ROPRankingDataset`: データ読み込み、前処理、ペアワイズサンプル生成
- `PairwiseDataLoader`: Leave-One-Video-Out分割のサポート
- 動画ごとのMin-Max正規化
- Hard negative sampling（ルールベーススコア上位50%から半数）

#### model.py
- `PairwiseRanker`: Feature-based MLP
- `compute_pairwise_loss()`: Margin Ranking Loss
- `rank_images()`: 推論時のランキング
- 代替損失関数（RankNet, TripletLoss）も実装

#### trainer.py
- `Trainer`: 学習ループ、チェックポイント保存
- `EarlyStopping`: 過学習防止
- `run_lovo_cv()`: LOVO交差検証の実行

#### evaluator.py
- `Evaluator`: 評価指標の計算
- Top-K Precision/Recall, NDCG@K, MRR
- ベースラインとの比較レポート

### 変更理由 (Reason for Change)
- ルールベースAIの固定重み（0.4, 0.4, 0.2）は最適ではない可能性
- ヒトの選択パターンを学習することで一致率向上を期待
- Pairwise Rankingは「相対的な順序」を学習するため、少ないデータでも有効
